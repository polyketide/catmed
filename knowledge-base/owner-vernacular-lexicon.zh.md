# 主人用语对照表（中文病友社群 → 标准术语 → 知识库路由）

> 生成于 2026-07-27 · 语料实测词频 · **本文件不含任何医学结论**
>
> **⛔ 这不是证据文件，是一张路由表。** 它只做两件事：把中文病友社群的口语/缩写**翻译**成标准术语，并**指向**知识库中已逐字核实的文件。
> 它**不给剂量、不给建议、不下结论**——所有医学内容仍然只存在于它指向的那些文件里，并只以 PubMed 一手文献为依据。
> 因此本文件**没有 `## 原文摘录` 段落**：它不主张任何需要溯源的事实。
>
> **为什么用中文写。** 知识库其余分析笔记以英文写成（见 `README.zh.md`）。本文件是刻意的例外——**它的研究对象本身就是中文**，翻译成英文会毁掉它的用途。
>
> **来源与边界。** 词条与频次来自一份私域病友群聊天导出的**统计**，用于确定"主人实际会怎么写"。**原文、昵称、猫名、城市均未进入本仓库**，本表只保留去标识化的用语本身。

---

## 0. 为什么需要这张表

受限 agent（`cat-owner-triage`）只能读 `knowledge-base/` 与 `guides/`。主人实际的提问长这样：

> 「我家 **cop6门1洛2**，**neu 0.44**，要不要打**瑞白**？」

这句话里**每一个关键信息都是缩写**。在本表建立之前，`结疗`、`网织`、`强饲`、`帕拉丁`、`仑伐` 在整个知识库中**检索命中为零**——知识库握有回答所需的全部证据，却读不懂问题本身。

> **⭐ 一个实测案例。** 有主人在群里说「结疗率大概 1%」。知识库里其实有足以核对它的数据（低级别 CR 76%、小细胞 ORR 85.7%、高级别缓解率 66%，见 `feline-oncology-literature-survey.md` §3），**但 agent 不认识「结疗」二字，因而无法把问题接到证据上。** 卡点不是知识，是语言。

## 1. 化疗方案骨架

| 社群写法 | 标准术语 | 说明 / 路由 |
|---|---|---|
| `cop` / `COP` | 环磷酰胺 + 长春新碱 + 泼尼松龙 | 语料中**最高频**方案，出现频次约为 CHOP 的 2.3 倍 → `feline-oncology-literature-survey.md` §3 |
| `chop` / `CHOP` | COP + 多柔比星 | ⚠️ 含多柔比星，**猫的毒性靶器官是肾**，见 `antineoplastic-drug-toxicity.md` |
| `cmop` | 以米托蒽醌替代多柔比星 | 与 CHOP 疗效相当的替代方案 → `feline-oncology-literature-survey.md` §3 |
| `lcop` / `lchop` / `L-COP` | 含门冬酰胺酶（L-asparaginase）的 COP/CHOP | `L` 指 L-门冬酰胺酶 |
| `covp` | COP + 长春花碱 | |
| `cop6` `chop16` `cop12` | 方案 + **已完成轮次** | 数字是**累计次数**，不是剂量 |

**方案串的读法。** `cop5花4培1` = COP 五轮 + 「花」四次 + 「培」一次。**串中的数字一律是次数，不是 mg。** 语料中位为 7 轮，最高 28 轮。

| 社群写法 | 标准术语 | 路由 |

| `门` `门冬` `培门` | 门冬酰胺酶 / 培门冬酶 | `antineoplastic-drug-toxicity.md`（猫中几乎无骨髓抑制） |

### ⚠️ 三个含义存疑的缩写——**标注存疑，不猜**

以下缩写在语料中高频出现，但**仅凭文本无法确定所指**。agent 遇到时应**要求主人澄清**，不得替其假定：

| 写法 | 可能含义 | 为什么不能判定 |
|---|---|---|
| `培N`（如 `培3`） | 培门冬酶 **或** 培美曲塞 | `培门1` 明确是培门冬酶；但裸写 `培5` 两者皆可能 |
| `花N`（如 `花4`） | 长春花碱 | 出现在方案串中时多半是长春花碱；⚠️ **但「花」也大量出现在猫名里**（花生、狸花、爆米花），**只有紧跟数字且位于方案串中才可作药物解**|
| `尼N`（如 `尼3`） | **未能确定** | 可能为泼尼松龙缩写，也可能为某种「-替尼」类药物；语料证据不足，**未作判定** |

> **⭐ 这三行是本表最重要的部分。** 猜错一个缩写，就等于把一句提问接到错误的药物条目上。**存疑必须显式标注**——这与本项目对社群符号语义的处理一致：拿不准就标记，然后去问懂的人（见 `docs/LITERATURE-PIPELINE-SOP.md` §7a 关于星标的记载）。

## 5. 状态与转归词（影响语气，不只是语义）

| 社群写法 | 含义 | agent 应如何反应 |
|---|---|---|
| `结疗` `结辽` `已结` | **结束疗程**（完成计划疗程） | ⚠️ **≠ 治愈，也 ≠ 完全缓解**，三者常被混用，必要时应请主人澄清 |
| `喵星` `去喵星` `返航` `彩虹桥` | **猫已离世** | ⛔ **立即切换为哀悼语气，停止一切医疗建议与追问。** |
| `⭐` `🌟` `✨` `💫` `🪐` | **同上——已离世** | ⛔ 昵称尾部的星标在本社群中表示"去了喵星"。**此语义由社群知情人确认**，不可由文本自行推断 |
| `🌈` | 同上（彩虹桥） | ⛔ 同上 |
| `复发` | 复发 | |
| `缓解` `CR` | 完全缓解 | `feline-oncology-literature-survey.md` §3 |
| `逆推` | 逐步减量 / 反向推算方案 | 语料中多与 FIP 用药相关 |

> **⭐ 状态词是本表中唯一会改变回应"语气"而非"内容"的一类。** 把 `⭐` 误读为装饰、继续追问治疗方案，是这份工作里代价最高的一种错误。

## 6. 使用纪律

1. **本表只翻译与路由，不产生结论。** 任何医学判断必须来自它指向的知识库文件，且那些文件的每一条依据都已对 PubMed 记录逐字核对。
2. **存疑的缩写必须显式提出澄清**（见 §2 末），不得替主人假定所指药物。
3. **不得用本表反向生成"标准写法"要求主人。** 主人怎么写就怎么读；适配的是 agent，不是使用者。
4. **词频反映的是一个特定社群、特定时段的用语**，会随时间和群体漂移。发现无法解析的新写法时，正确做法是**如实说不认识**，而不是猜一个最像的。
